# GPU_EXISTING_CORPUS_OVERLAP — overlap registry between the GPU corpus and pre-existing analyses

last_checked: 2026-09-18
knowledge_as_of: 2026-09-18
scope: `domains/gpu_systems/` against `domains/hpc_systems_operations/` (imported) and `domains/ai_hpc_systems/` (`EXTERNAL_IMPORT_PENDING`)
companion: [`GPU_PENDING_FULLTEXT.md`](GPU_PENDING_FULLTEXT.md)

## Purpose

So that the AI/HPC corpus and the GPU corpus never independently explain the same paper twice.
One row per paper for which an overlap question arises: every paper whose ledger row or deep-analysis
front matter carries `EXISTING_CORPUS_DUPLICATE`, `GPU_DELTA_ANALYSIS` or `KNOWN_EXTERNAL_CORPUS_NOT_IMPORTED`,
plus every paper with a **real hit** in `domains/hpc_systems_operations/`.

## Preamble — rules this document is bound by

1. **`domains/ai_hpc_systems/` holds no corpus in this repository.** Its `DOMAIN_CONTEXT.md` records status
   `EXTERNAL_IMPORT_PENDING`: a ~80-paper AI/HPC corpus produced in a separate external workspace (2026-09-06),
   **not imported**, and *"nothing about its content is asserted here — do not infer venues, paper counts by venue,
   topic coverage, or specific findings"*. Therefore, for every paper flagged `KNOWN_EXTERNAL_CORPUS_NOT_IMPORTED`:
   **`Existing path` is the literal token `KNOWN_EXTERNAL_CORPUS_NOT_IMPORTED`, `Existing depth` is `UNKNOWN`,**
   and the `Action` cell states that duplication is **NOT DETERMINED**. Such a row is **never** `NO_EXISTING_ANALYSIS`,
   and no guess is made about whether the external corpus contains the paper. Absence from this repository is
   not evidence of novelty (`governance/ANTI_HALLUCINATION_RULES.md`).
2. **`domains/hpc_systems_operations/` *is* imported**, so its hits are real and are given with the exact file,
   the exact line where the ledgers cite one, and the exact depth that can be verified by reading it — e.g.
   "one-line grading row, `ABSTRACT-UNREAD`" versus "full-text record including a specific critique".
   Where a deep analysis in `domains/gpu_systems/` **corrected** the prior record, the correction is stated.
3. **Raw TOC dumps are not existing analyses.** `domains/hpc_quantum/corpus/quantum-hpc-survey/working-evidence/`
   holds raw proceedings tables of contents. They are evidence that a paper exists in a volume, never an analysis,
   and **no row is created for them.** The same treatment is applied to program listings inside the operations
   corpus (SC26 finalists tables): they are named as the hit, and the Action says `NO_EXISTING_ANALYSIS`.
4. **`EXISTING_CORPUS_DUPLICATE`: zero occurrences.** A repo-wide grep finds the token only in
   [`_ANALYSIS_TEMPLATE.md`](../corpus/_ANALYSIS_TEMPLATE.md) (as a vocabulary item) and in six deep analyses that answer it
   **"no"** or **"cannot be determined for the external corpus; no within this repository"**. No paper in this
   corpus is recorded as a duplicate of an existing in-repository analysis.
5. **Dual-flagged papers.** A few papers carry *both* a real `hpc_systems_operations` record *and* the external flag.
   For those the `Existing path` cell names the operations file **and** the literal external token, and the depth
   cell gives the verifiable operations depth and states `UNKNOWN` for the external corpus. This keeps rule 1
   intact while not suppressing a hit that is real.
6. **Disagreements are recorded, not reconciled** (`governance/KNOWLEDGE_BASE_RULES.md` rule 6). Where a ledger
   or a deep analysis disagrees with a census row or with the file on disk, both readings appear in the row and
   the row says which I followed. See §4.

### Action vocabulary

| Action | Meaning |
|---|---|
| `REUSE` | An existing analysis elsewhere in this repository already covers what this corpus needs. Cite it; do not re-analyse. |
| `GPU_DELTA_ONLY` | An existing analysis holds the non-GPU-specific content. Only the GPU-specific delta is owed — and, for the seven rows in §1, **is already written**. |
| `NEEDS_DEEPER_GPU_ANALYSIS` | A real prior record exists but is shallow, and no GPU deep analysis exists yet. A GPU analysis (written as a delta) is owed. |
| `NO_EXISTING_ANALYSIS` | The repo-wide grep found no analysis — only census rows, program listings or bibliographic rows. A `Existing path` may still be given: it is where the *non*-analysis record sits. |
| `KNOWN_EXTERNAL_CORPUS_NOT_IMPORTED` | Duplication against the external AI/HPC corpus is **not determined**. Not a claim of absence. |

### How the flag basis was decided for each cluster

Some verdict ledgers apply `KNOWN_EXTERNAL_CORPUS_NOT_IMPORTED` **per row**; others apply it to a **class**
("every LLM-serving row below", "every deep-learning-facing compiler/fusion paper below"), and one
([`_LEDGER_multi_gpu_communication.md:15`](../corpus/_LEDGER_multi_gpu_communication.md)) applies it to **every row in the cluster** and states that
*"a central overlap registry must carry this flag"*. Each §3 row therefore carries an explicit *Flag basis*:
`blanket`, `named` (enumerated in that ledger's own list) or `class` (the row's own text names the LLM/DL/serving/tensor
subject the caveat is about). Rows judged only by class are marked as such so the judgement is auditable and reversible.
