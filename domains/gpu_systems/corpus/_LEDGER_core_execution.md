`evidence_read` records what was actually read — a verdict reached from an
abstract or a census row says so and **may not be used to justify a deep analysis**.

**Counterfactual answer** column records the answer to: "If a generic
accelerator or a CPU were used instead, would the core contribution be
substantially the same?" `NO` = the contribution depends on a named
GPU-specific property. `NO (title/census-level)` = the GPU-specific mechanism
is evident from the confirmed title/session/abstract but the paper was not
read, so the answer is provisional.

**Simulated vs measured** is recorded explicitly for every deep-analysed paper,
because this cluster mixes simulator studies with real-silicon dissection and a
simulated area/power number is not a measured one.

**Tooling constraints that shaped access states** (do not re-derive):
`dl.acm.org` → 403, `ieeexplore.ieee.org` → 418, `dblp.org` → robots-blocked,
`arxiv.org/search` / `export.arxiv.org` / `web.archive.org` → unavailable.
Several ISCA 2025 papers in this cluster (LazyGPU, UGPU) are **genuinely open
access on ACM DL** but unreachable from this environment; they are recorded
`PENDING_FULLTEXT`, **not** `CLOSED_ACCESS`.

**Two source-assignment corrections made in this pass** (both verified):
1. arXiv `2501.12084` is **not** "Dissecting and Modeling the Architecture of
   Modern GPU Cores" (MICRO 2025). It is Luo et al., *"Dissecting the NVIDIA
   Hopper Architecture through Microbenchmarking and Multiple Level Analysis"* —
   the extended journal version of the **IPDPS 2024** Hopper paper. The MICRO 2025
   paper was obtained instead from the UPCommons institutional PDF.
2. The IPDPS 2024 Hopper paper's own arXiv record is `2402.13499` (v1,
   2024-02-21; six authors). The extension `2501.12084` adds a seventh author
   (Hongyuan Liu) and adds the partitioned-L2 and TMA analyses. The two are kept
   distinct in `GPU-IPDPS24-61`.

## 3. Cluster-level observations recorded during this pass

1. **The core model this cluster's simulation papers assume is contested by the
   cluster's own strongest paper.** `GPU-ISCA24-61` (GhOST) adds out-of-order
   issue on top of Accel-Sim's scoreboard-plus-operand-collector core, and
   diagnoses its predecessor LOOG's failure as *operand-collector congestion*.
   `GPU-MICRO25-61` measures that same baseline at **34.03% MAPE** against a real
   RTX A6000 and finds that real Turing/Ampere/Blackwell cores use **compiler
   control bits, not a scoreboard**, and have **no operand collector units** at
   all (because a compiler-set stall counter requires statically known
   issue-to-writeback latency, which an operand collector would destroy). The
   two papers are in direct tension about what the issue stage is; neither
   evaluates against the other. **Any future work in this cluster must state
   which core model it assumes.** The same tension applies to the unread
   *Warped-Compaction* (HPCA 2025).

2. **Simulated vs measured splits this cluster almost exactly in half, and the
   measured half is newer.** Simulator-based: GhOST (ISCA'24), CARS (MICRO'24),
   ThreadFuser's projections (MICRO'24). Real-silicon dissection: the GPU NoC
   paper (MICRO'24), Hopper (IPDPS'24), modern GPU cores (MICRO'25, which uses
   measurement *to fix* the simulator), Blackwell (IPDPS'26, which states
   outright that Accel-Sim and GCoM **cannot** model TMEM or the decompression
   engine). The 2024→2026 direction of travel is from proposing mechanisms in
   simulation toward measuring what vendors already shipped.

3. **Matrix-instruction issue scope widened and then narrowed in two
   generations** — a lineage only visible by reading `GPU-IPDPS24-61` and
   `GPU-IPDPS26-61` together: warp-scope `mma` (Ampere/Ada) → **warp-group**
   `wgmma` (Hopper, 128 threads, 128 cycles at `m64n256k16`) → back to
   **warp-scope** `tcgen05.mma` (Blackwell B200, 11.4 cycles at `m256n256k16`),
   with the removal of warp-group synchronisation named as a cause of the
   latency drop. Accumulator placement moved the opposite way: register file →
   register file → **TMEM**.

4. **Two independent 2024 papers converge on partitioned-L2 non-uniformity.**
   `GPU-MICRO24-63` measures it by SM pinning and correlation clustering
   (~200 vs ~400 cycles across an A100/H100 partition, plus TPC/GPC and an
   undocumented **CPC** level on H100); the Hopper extension measures it by
   p-chase (near/far hit 208/356.6 cycles on A100, 258/414.1 on H800). Different
   methods, same structure. **This is the best-corroborated microarchitectural
   fact in the cluster.**

5. **Register spill/fill became a first-class GPU cost in 2024.**
   `GPU-MICRO24-61` (CARS) measures **40.4% of in-core L1D accesses** on a real
   V100 as ABI register traffic, and shows an idealised *unlimited-register*
   machine recovers only 1.06× where CARS recovers 1.26× — i.e. the cost is the
   memory *instructions*, not capacity. Independently, `GPU-MICRO24-62`
   (ThreadFuser, same group, same venue) lists CPU-compiler register allocation
   causing "unnecessary spills/fills" under SIMT as a named limitation.

6. **Power is an unlisted confound for every instruction-throughput number in
   this cluster.** `GPU-IPDPS24-61` shows H800 `wgmma` throughput depends on the
   *contents* of the input matrices: zero-initialised inputs draw under 200 W
   and reach >95% of peak, random inputs hit the 350 W limit and drop the clock
   below the 1620 MHz whitepaper figure. The Hopper paper reports matrix
   throughput as `Total_OPS / Duration` rather than in cycles precisely to
   expose this. `Lit Silicon` (ISCA 2026) extends the same concern to multi-GPU
   thermal coupling.
