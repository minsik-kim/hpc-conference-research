# PART A — 실험 설계

# §1. F1 첫 실험 — Retention 해상도가 RCA 품질을 파괴하는가 (Q-δ)

`09` §12.2의 Q-δ. **이것이 F1의 중심이며, 첫 실험은 Q-δ 하나만 검증한다.** 비용 축(Q-α)이나 적응 샘플링(Q-γ)은 첫 실험에 넣지 않는다 — 하나의 실험에서 두 가지를 주장하면 둘 다 약해진다.

## 1.1 가설

> **H1 (주가설):** 다계층 HPC telemetry를 시간 방향으로 downsampling할 때, **이상 탐지 품질($Q_{detect}$, $T_{detect}$)의 열화율보다 원인 국소화·진단 품질($Q_{localize}$, $Q_{RCA}$)의 열화율이 유의하게 크다.**
>
> **H1a (메커니즘 가설, 이것이 novelty의 핵심):** 그 비대칭의 원인은 진폭 정보 손실이 아니라 **계층 간 lag / 사건 순서(ordering) 정보의 손실**이다.

**H1a가 H1보다 중요하다.** H1만 보이면 "샘플링을 줄이면 나빠진다"는 자명한 결과이고, TelemetrySuffBench(2026)가 이미 합성 데이터로 보였다(`09` §4.1 HIT 1). **H1a가 참이면 예측이 따라온다: ordering을 보존하는 요약(예: 첫 초과 시각, 부호 변화 시각, 극값 시각)을 함께 저장하면 같은 바이트로 RCA 품질을 유지할 수 있다.** 그 예측의 검증이 실험을 자명하지 않게 만든다.

## 1.2 필요 데이터

`08` §2.1(a) 전체. 최소 요건:

| 항목 | 최소 요건 | 없으면 |
|---|---|---|
| 전해상도 다계층 코퍼스 | **1 s**, CPU·GPU/DCGM·fabric·Lustre·power·CDU·logs | 실험 불성립 |
| clock offset 시계열 | 소스별, 실험 구간 전체 | **lag 측정 자체가 무의미** — 가장 흔한 실패 원인 |
| 물리·fabric·저장 토폴로지 이력 | 실험 구간에 유효한 매핑 | cascade 경로 재구성 불가 |
| job 배치 이력 | 전체 할당 노드 리스트 + 시작/종료 초 단위 | 간섭 원인 클래스 배제 불가 |
| 인시던트 사후판정 | 구조화된 원인 클래스 + 시각 + 영향 노드 | ground truth 없음 |

## 1.3 최소 관측 기간

| 목적 | 기간 | 근거 |
|---|---|---|
| **예비 실험 (계속/폐기 판정용)** | **전해상도 6개월** | 효과 크기 추정에 필요한 최소 인시던트 수 확보 목적. **여기서 폐기 판정이 나오면 본 실험에 들어가지 않는다** |
| 본 실험 | **전해상도 12개월 이상** | 계절성(외기·냉각 부하), 시스템 성숙 단계, 펌웨어 전이를 포함 |
| 교란 측정 | 수락시험 창 + production 중 유지보수 창 3회 이상 | `08` §2.1(c) |

**⚠️ 6개월에서 인시던트 수가 부족할 위험이 실재한다.** §1.6의 ground truth 규모 문제 참조. 부족하면 기간이 아니라 **인시던트 수**를 기준으로 판단할 것.

## 1.4 최소 규모

- **노드 수:** 원인 클래스별로 최소 다수의 독립 사례가 필요하므로 전 시스템. 단 §1.7의 대조군 설계가 규모보다 중요
- **계층 수:** **최소 4계층**(GPU/노드 + fabric + 저장 + 시설). `09` §5.3에 따라 계층 수가 conjunction의 한 축이다. Beacon(NSDI'19)이 4계층 40,960노드를 이미 했으므로 **3계층으로는 반례에 진다**
- **시스템 수:** 첫 실험은 1시스템으로 가능. 단 §1.10 참조

## 1.5 통제 교란 (controlled perturbation)

관측만으로는 원인 클래스별 label이 부족하므로 **주입 실험이 필수**다. 그러나 주입만으로 하면 `09` §11 C5의 *"주입 anomaly만"* 반론에 걸린다. **주입 + 실관측 병용.**

| 클래스 | 주입 방법 | 주의 |
|---|---|---|
| CPU 경합 | 노드 내 CPU burner를 코어 부분집합에 | |
| 메모리 대역 경합 | STREAM 유사 부하 공존 | |
| GPU throttle | power cap 하향 또는 clock cap | **실제 열 throttle과 신호가 다르다.** 두 경로를 구분해 기록할 것 |
| fabric 혼잡 | 이웃 노드에서 all-to-all 부하 주입 | 실제 혼잡은 경로 공유 패턴이 다르다 |
| 저장 경합 | 동일 OST 대상 I/O 폭주 | |
| fail-slow 노드 | **주입 불가에 가깝다.** 이것이 실관측이 필요한 이유 | |
| 냉각 이상 | **주입 금지.** 시설 안전 | 실관측 + 계획 정비 이력만 |

**주입 실험 프로토콜:** 각 클래스 × 강도 3수준 × 반복 다수, 무작위 시각, **동시 대조군 노드 확보**, 주입 시각·대상·강도를 기계 판독 가능한 형태로 기록. 주입 로그가 곧 ground truth다.

## 1.6 Ground truth

**두 종류를 분리한다.**

| 종류 | 출처 | 강점 | 약점 |
|---|---|---|---|
| **GT-inject** | §1.5의 주입 로그 | 정확·풍부·클래스 균형 | 실제와 신호 분포가 다르다 |
| **GT-observed** | 운영자 구조화 사후판정(`08` §2.2(c)) + RMA 확인 | 실제 | **수가 적다.** 심사 기준선: Kaleidoscope 843건, ClusterRCA 739건 |

**GT-observed 수가 이 실험의 최대 병목이다.** 6개월에 확정 원인 인시던트가 100건 미만이면 통계적 주장이 어렵다. **대응:** (i) 사후판정 절차를 운영 개시와 동시에 시작해 축적 시간을 벌 것, (ii) RMA를 지연 고정밀 label로 활용, (iii) 부족하면 GT-inject로 주장하고 GT-observed로 **일관성 확인**만 하되 논문에서 그렇게 정직하게 쓸 것.

**⚠️ silent degradation은 티켓이 거의 없으므로 GT-observed에 sampling bias가 있다**(`09` §11 C5). 반드시 논문에 명시.

## 1.7 Baseline

| Baseline | 내용 | 역할 |
|---|---|---|
| **B0 전해상도** | 1 s 원본 | 상한 |
| **B1 균일 downsampling** | 5 s / 30 s / 1 min / 5 min / 15 min 평균 | 주 비교 대상. 운영 기본값 |
| **B2 균일 + 통계 요약** | 평균 + min/max/stddev/분위수 | 실무에서 흔한 절충. **진폭 정보는 보존, ordering은 파괴** → H1a의 핵심 대조군 |
| **B3 모델측 축소** | Prodigy(SC'23)·NodeSentry(SC'25)·Tuncer(TPDS'19) 계열 feature selection, **원본은 전해상도 유지** | `09` §4.1의 시스템측/모델측 구분을 실험으로 구현. 이것이 없으면 심사자가 "그냥 feature selection 아닌가"로 읽는다 |
| **B4 lossless 압축** | zstd 등, 해상도 무손실 | 비용만 줄고 품질 손실 0인 비교점 |
| **B5 ordering 보존 요약 (제안)** | 같은 바이트 예산에서 첫 초과 시각·극값 시각·부호변화 시각 등 **시간 marker**를 보존 | **H1a의 예측 검증.** B2와 같은 바이트에서 RCA 품질이 더 높아야 한다 |
| **B6 Hindsight식 retroactive** | 인시던트 시 소급 pin(binary keep/discard) | `09` §4.3이 지정한 최근접 발표 선례와의 명시적 비교 |

**B2와 B5의 대비가 실험의 심장이다.** 두 baseline은 바이트 예산이 같고 진폭 정보량도 유사하지만 ordering 보존 여부가 다르다. 여기서 차이가 없으면 H1a는 거짓이다.

## 1.8 지표

| 축 | 지표 |
|---|---|
| $Q_{detect}$ | precision/recall/F1, PR-AUC (클래스 불균형이므로 ROC-AUC 단독 금지) |
| $T_{detect}$ | 사건 시작~탐지까지 지연 분포(중위·95분위) |
| $Q_{localize}$ | 영향 노드 집합 식별 precision/recall, top-k 노드 정확도 |
| $Q_{RCA}$ | **원인 클래스 acc@1 / acc@3**, 계층 식별 정확도, 혼동행렬 |
| **lag 재구성 오차** | 계층 간 사건 시차의 추정 오차(초). **H1a의 직접 측정량** |
| **ordering 보존율** | 실제 cascade 순서를 정확히 복원한 사례 비율 |
| 비용 | 바이트/일, 저장 TB-month, 쿼리 스캔량·지연 |

**주요 산출물:** 해상도를 x축으로 한 **$Q_{detect}$ 곡선과 $Q_{RCA}$ 곡선의 분리**, 그리고 그 분리를 lag 재구성 오차로 **설명**하는 그림.

## 1.9 Ablation

1. **계층 제거** — 4계층 → 3 → 2. 어느 계층의 해상도가 RCA에 결정적인가
2. **계층별 비대칭 정책** — 예: fabric만 1 s, 나머지 1 min. 계층별 해상도 민감도
3. **원인 클래스별 분해** — 어느 원인 클래스가 해상도에 가장 민감한가(fabric 혼잡이 가장 민감할 것으로 예상되지만 **예상은 결과가 아니다**)
4. **ordering marker 종류별** — B5에서 어떤 marker가 기여하는가
5. **탐지기 종류 무관성** — 통계적 방법 / 트리 앙상블 / 시계열 딥모델 각각에서 비대칭이 재현되는가. **재현되지 않으면 결과는 모델 artifact다**
6. **clock skew 민감도** — 인공적으로 offset을 주입해 lag 측정의 견고성 확인

## 1.10 Cross-system 평가

첫 실험은 1시스템으로 성립하지만 **SC 심사에서는 거의 확실히 요구된다.**

- **1차 (필수):** 한강 + 구시스템(누리온 등) — 계층 수가 적어도 CPU·저장·전력은 있다. F2와 데이터가 공유된다
- **2차 (강력 권장):** **M100 ExaData**(CINECA, 공개·다운로드 가능), **HPC-ODA**(Netti 계열) — 계층 구성이 다르므로 "비대칭이 아키텍처 독립적인가"를 볼 수 있다. `09` §8.3의 "다리는 데이터셋" 논지와 부합
- **주의:** 공개 데이터셋은 대개 **이미 집계된 해상도**로 배포된다. 그것으로는 downsampling 실험의 상한이 낮다. 논문에서 이 한계를 명시할 것

## 1.11 실패 기준 — 어떤 결과가 나오면 아이디어를 버려야 하는가

> **이 절이 이 문서의 존재 이유다.**

| # | 관측되면 | 판정 |
|---|---|---|
| **F1-K1** | **$Q_{RCA}$의 열화율이 $Q_{detect}$의 열화율과 통계적으로 구별되지 않는다** (여러 탐지기·여러 원인 클래스에서) | **H1 거짓. 후보 폐기.** 비대칭이 없으면 논문의 전제가 없다 |
| **F1-K2** | 비대칭은 있으나 **B2(통계 요약)가 B5(ordering 보존)와 차이가 없다** | **H1a 거짓 = novelty 소멸.** 남는 것은 "줄이면 나빠진다"이고 그것은 TelemetrySuffBench가 이미 했다. → **폐기 또는 비용축(Q-α)으로 전면 이동**(단 그것은 DCDB SC'19와 정면 경쟁) |
| **F1-K3** | **1 min에서도 $Q_{RCA}$가 실용적으로 충분하다**(예: acc@3가 전해상도 대비 유의하게 낮지 않다) | **운영적으로 좋은 결과이지만 연구로는 폐기.** 문제가 존재하지 않는다. → 정직하게 negative result로 워크숍에 낼 것(그 자체로 커뮤니티에 유용하다) |
| **F1-K4** | 비대칭이 **특정 탐지기에서만** 나타난다 | 모델 artifact. 폐기 또는 "탐지기 선택과 해상도의 상호작용"으로 재정의(약한 논문) |
| **F1-K5** | GT-observed가 6개월에 **수십 건 수준**이고 GT-inject와 결과가 반대 방향 | 주입이 실제를 대표하지 않는다. → 기간 연장 또는 폐기. **GT-inject만으로 SC 주장은 하지 말 것** |
| **F1-K6** | **DB 문헌(VLDB/SIGMOD/ICDE/EDBT/CIDR)에서 retention 해상도 vs 하류 분석 품질 스윕 논문이 발견된다** | **문헌 기반 폐기.** 실험 착수 전에 확인할 일이며, `08` §4.4·`12`의 최우선 항목 |
| **F1-K7** | PIKA CLUSTER'20 또는 Tuncer TPDS'19에서 rate 민감도 연구가 이미 있다 | 비용축·HPC 최초 주장 약화. 폐기는 아니나 retention 축으로 더 좁혀야 함 |

## 1.12 예상되는 심사 비판 (강도 순)

1. *"가설은 FDI에서 정리이고(isolability ⊃ detectability, Krysander & Frisk 2008; Rosich 2012) 2026년에 벤치마크로 확인되었다. 무엇이 새로운가?"* → **답: 정성적 정리를 인정하고, 바이트·rate·retention으로 정량화한 것이 없다는 점 + Q-δ의 메커니즘(ordering 손실)을 주장. 인정하지 않고 "미발표"라고 쓰면 desk reject**(`09` §4.4)
2. *"AWStream(SIGCOMM'18)이 frame rate를 knob으로 하는 accuracy-vs-bandwidth frontier를 이미 했다"* → **답: 채택하고 delta 3개(retention/age, 교란 비용항, 진단 품질항)를 명시**
3. *"DCDB(SC'19)가 HPC 수집 비용을 이미 측정했다"* → 답: 인정. GPU·retention·품질 축이 없음을 명시
4. *"Beacon(NSDI'19)이 4계층 40,960노드를 이미 했다"* → 답: Beacon은 압축·캐싱이고 해상도-품질 trade-off가 아님. 단 **가장 위험한 인용이므로 related work에서 정면으로 다룰 것**
5. *"주입 anomaly로 RCA를 평가한 것 아닌가"* → 답: GT-observed 병용 결과 제시. 수가 적으면 정직하게
6. *"1개 시스템"* → 답: §1.10
7. *"비용 주장이 추정치 아닌가"* → 답: `08` §2.1(b)(c)의 실측. **이것이 없으면 가장 아픈 질문이 된다**

# §2. F2 첫 실험 — 세대 간 전이 손실의 원인 분해

## 2.1 가설

> **H2:** 동일 기관의 서로 다른 세대 시스템 간 운영 이상탐지/진단 모델 전이 손실은 **분해 가능**하며, 그 손실의 지배적 요인은 하드웨어 세대 변화가 아니라 **schema 변화와 workload mix 변화**다.

**H2의 방향을 미리 정하지 말 것.** 위 문장은 검증 대상 방향이며, 반대 결과(하드웨어가 지배)도 발표 가치가 있다. 다만 **분해 자체가 성립하지 않으면** 논문이 없다 → §2.9.

## 2.2 필요 데이터 / 기간 / 규모

- 구시스템 telemetry 아카이브(**`08` §2.4: 폐기 금지**), 신시스템 telemetry
- **metric schema 사전(양 세대)** — 이것이 실질적 작업량의 대부분(`09` §11 C2)
- 세대별 workload mix 이력, 스케줄러 정책 변경 이력, 펌웨어/드라이버 변경 이력
- 기간: **각 세대 최소 3개월**, 시간순 분할 가능하도록
- 규모: 세대 2개(내부) + 공개 데이터셋 2개(M100 ExaData, HPC-ODA) = **평가 대상 4**

## 2.3 Ground truth

각 세대의 장애/이상 label. **세대 간 label 정의가 다르면 전이 손실과 label 정의 차이가 혼동된다.** → `08` §2.5의 통일된 원인 taxonomy를 양 세대에 소급 적용할 수 있는지가 실험의 전제. 불가능하면 **공통 부분집합으로 축소**하고 그 사실을 명시.

## 2.4 통제 교란

관측 데이터만으로는 shift 요인이 얽혀 있으므로 **합성 shift 주입**으로 분해한다:

| 요인 | 통제 방법 |
|---|---|
| **schema** | 동일 세대 안에서 metric 이름/단위/부분집합을 인공적으로 변형해 학습·평가. schema만 바뀐 순수 효과 |
| **workload mix** | 동일 세대 안에서 job mix를 재표본화(분야·규모 분포를 타 세대와 일치시킴) |
| **하드웨어 세대** | 위 두 요인을 정렬한 뒤 남는 차이 |
| **스케줄러 정책** | 정책 변경 전후 구간으로 분할 |

## 2.5 Baseline

| B0 | 동일 세대 내 학습·평가 (상한) |
|---|---|
| B1 | 세대 A 학습 → 세대 B 평가, 무보정 (하한) |
| B2 | 단순 정규화/표준화만 |
| B3 | 무차원 파생량만 사용(비율·정규화 지표) — **invariant representation 가설** |
| B4 | 소량 target label로 fine-tuning (label 효율 곡선) |
| B5 | **CENTILE 계열 adapter** — 반드시 비교. 없으면 심사에서 즉사 |
| B6 | target-only 학습 (전이가 필요한지 자체 검증) |

**B6가 중요하다.** target-only가 전이보다 좋으면 전이 연구의 전제가 무너진다.

## 2.6 지표

- 성능: F1, PR-AUC, 원인 acc@k — 세대 쌍별
- **transfer-penalty matrix** $P_{ij}$ = 세대 i 학습 → 세대 j 평가의 상대 손실. **이것이 공개 artifact**
- label 효율 곡선: target label 수 대비 성능
- shift 크기 지표: 분포 거리(MMD 등) — 손실과의 상관
- **분해 기여율**: 각 요인이 설명하는 손실 비율 + 신뢰구간

## 2.7 Ablation

metric 부분집합별 전이성(어떤 metric이 세대를 넘는가) / 시간 창 길이 / 원인 클래스별 전이성 / **시간순 분할 vs 랜덤 분할 대비**(랜덤 분할을 쓰면 TOSEM data-splitting 논문 하나로 죽는다 — `09` §11 C2)

## 2.8 Cross-system 평가

내부 2세대 + M100 ExaData + HPC-ODA. **off-diagonal이 주장의 대상**(`09` §6.3).

## 2.9 실패 기준

| # | 관측되면 | 판정 |
|---|---|---|
| **F2-K1** | **요인 분해가 성립하지 않는다** — 각 요인의 기여 신뢰구간이 서로 겹치고 합이 전체 손실과 맞지 않는다 | 폐기. 분해가 기여의 전부다 |
| **F2-K2** | **B3(무차원 파생량)이 전이 손실을 거의 없앤다** | 좋은 실용 결과이나 연구로는 약하다. "정규화하면 된다"는 한 문단 결론 → 워크숍 |
| **F2-K3** | **B6(target-only)가 모든 전이 방법보다 낫다** | 전이 문제가 존재하지 않는다. 폐기 |
| **F2-K4** | schema 정렬 후 손실이 거의 사라진다 | 기여가 "schema를 맞춰라"로 축소 → 데이터 관리 실무 권고. 워크숍 |
| **F2-K5** | 2026–2027 중 동일 분해를 수행한 논문이 발표된다 | 문헌 기반 폐기. **가장 빠르게 침식되는 후보이므로 3개월 주기로 확인** |

## 2.10 예상 심사 비판

1. *"CENTILE·SeT-Diff·Farooq가 이미 있다"* → 방법이 아니라 **측정/분해**가 기여임을 서론에서 못 박을 것
2. *"세대가 2개인데 무엇을 일반화하는가"* → 공개 데이터셋 2종 추가 + off-diagonal 프레이밍. **약점을 숨기지 말 것**
3. *"Prodigy(SC'23)가 이미 두 시스템에서 평가했다"* → 그것은 방법의 견고성 확인이고 손실 분해가 아님
4. *"schema 정렬이 연구의 대부분 아닌가"* → 정렬 사전을 artifact로 공개하여 노동을 기여로 전환

# §3. F3 첫 실험 — 운영 label의 소스 간 불일치 측정

**전제:** SC26 ORNL 논문 확인 후 착수(`10` §3, 3위 항목).

## 3.1 가설

> **H3:** HPC 운영에서 "노드 장애/이상" label은 소스(모니터링 알람 / Slurm drain reason / health check / 티켓 / RMA)에 따라 **체계적으로 불일치**하며, 그 불일치는 무작위 잡음이 아니라 **원인 클래스에 따라 구조화**되어 있다.
>
> **H3a:** 소스 불일치를 무시하고 단일 소스를 정답으로 쓰는 관행은 이상탐지 모델의 보고 성능을 **체계적으로 편향**시킨다(방향은 검증 대상).

**H3a가 실용적 함의를 만든다.** H3만으로는 "label이 지저분하다"는 관찰이다.

## 3.2 필요 데이터 / 기간 / 규모

- `08` §2.5 전체 — **소스를 통합하지 않은 원본**. 통합된 상태로 저장되어 있으면 실험 불가
- 계획 정비 일정(계획-비계획 confound 분리)
- 기간: **최소 12개월**(RMA 지연이 수 주~수 개월이므로 짧으면 지연 label이 비어 있다)
- 규모: 전 시스템. 원인 클래스별 사례 수가 실질 제약
- **Slingshot switch counter** — 없으면 네트워크 원인 클래스가 붕괴(`09` §11 C5)

## 3.3 Ground truth — 이 실험에서는 GT가 연구 대상이다

**gold set 구축이 실험의 절반이다:**
- 무작위 표본 인시던트에 대해 **복수 운영자가 독립적으로** 원인 판정
- **inter-rater agreement (Cohen/Fleiss κ)** 측정 — 이것이 첫 번째 결과
- 불일치 사례를 합의 절차로 해소하고 **해소 과정 자체를 기록**(무엇이 불일치를 만드는가)
- RMA 확인 결과를 **지연 고정밀 label**로 사용해 초기 판정을 사후 채점

**⚠️ `09` §11 C4의 반론: "inter-rater agreement가 낮으면 무엇을 결론 내리는가?"** → 사전에 답을 준비할 것: 낮은 κ 자체가 결과이며, 그때 필요한 것은 더 나은 모델이 아니라 **판정 프로토콜**이라는 것이 논문의 주장이 된다. 이 논리를 미리 세워두지 않으면 낮은 κ가 실패로 읽힌다.

## 3.4 통제 교란

§1.5의 주입 실험을 재사용. 추가로 **주입된 사건에 대해 각 소스가 무엇을 기록했는가**를 관측 — 이것이 소스 감도(sensitivity) 측정이며 관측 데이터로는 얻을 수 없다.

## 3.5 Baseline / 비교 대상

| B1 | 단일 소스를 정답으로 하는 관행 (알람만 / drain만 / 티켓만) |
|---|---|
| B2 | 소스 합집합(OR) — 흔한 실무 |
| B3 | 소스 교집합(AND) — 고정밀 저재현 |
| B4 | 다수결 |
| B5 | weak supervision 결합(Snorkel 계열) — **방법론은 닫혀 있으므로 baseline으로만** |
| B6 | RMA만 (지연 고정밀) |

각 baseline label로 **동일한 이상탐지 모델**을 학습·평가하여 보고 성능이 어떻게 달라지는지 측정 = H3a.

## 3.6 지표

- 소스 쌍별 일치도 κ, 원인 클래스별 κ
- 소스별 감도·정밀도(주입 사건 기준)
- 시간 정합: 소스 간 사건 시각 차이 분포
- **label 선택이 보고 F1/PR-AUC를 바꾸는 폭** ← H3a의 핵심 수치
- 계획/비계획 confound 제거 전후 차이
- 원인 클래스 혼동행렬(운영자 간)

## 3.7 Ablation

소스 제거별 영향 / 원인 클래스별 분해 / 시간 정합 허용창 민감도 / 계획 정비 포함·제외 / 운영자 경력별 판정 차이(익명 집계)

## 3.8 Cross-system 평가

프로토콜의 이전 가능성을 보이는 것이 목표. **다른 센터에 프로토콜을 적용해 달라고 요청**하는 것이 가장 강한 형태이며, 이것이 이 후보의 협업 진입점이다. 공개 gold set 릴리스는 `08` §5.4의 제약 하에서.

## 3.9 실패 기준

| # | 관측되면 | 판정 |
|---|---|---|
| **F3-K1** | **소스 간 κ가 높다**(예: 대부분의 쌍에서 강한 일치) | 문제가 없다. 폐기. → 단 negative result로서 "HPC label은 클라우드와 달리 깨끗하다"는 발표 가치는 있다 |
| **F3-K2** | 불일치가 **무작위**여서 원인 클래스와 무관 | H3의 구조화 주장 실패. 잡음 보정 문제로 축소 → weak supervision 적용 = 닫힌 방법 → 폐기 |
| **F3-K3** | **label 선택이 보고 성능을 거의 바꾸지 않는다** | H3a 실패 = 실용적 함의 소멸. 관찰 논문으로 축소 → 워크숍 |
| **F3-K4** | inter-rater κ가 매우 낮고 **합의 절차로도 해소되지 않는다** | 원인 taxonomy 자체가 부적합. → taxonomy 재설계 후 재시작(폐기가 아니라 후퇴) |
| **F3-K5** | **SC26 ORNL 논문이 소스 간 불일치를 이미 측정** | 문헌 기반 폐기 또는 전면 재정의. **착수 전 확인 필수** |
| **F3-K6** | Slingshot switch counter 확보 실패 | 원인 클래스 3–4개로 축소 → 워크숍 수준. 폐기 권고 |
| **F3-K7** | GT-observed·gold set 규모가 100건대에 머문다 | 기준선(843/739) 미달. 기간 연장 또는 다센터 협업 없이는 SC 무리 |

## 3.10 예상 심사 비판

1. *"weak supervision은 해결된 기법이고 HPC 적용은 엔지니어링이다"* → **방법이 아니라 측정임을 명시.** labeling function을 만들고 F1이 올랐다고 보고하면 정확히 이 반론에 걸린다(`09` §11 C4)
2. *"Uptake(ISSRE'24)가 auto-mitigation의 label 파괴를 이미 정량화했다"* → 인용하고 차별화: HPC는 태울 label이 없다는 점(규모 차이)
3. *"평가 비판(Kim et al. AAAI'22)도 당신 것이 아니다"* → 인정하고 적용만 주장
4. *"ARGUS·Kaleidoscope가 이미 production 규모 원인 판별을 했다"* → **그들이 쓴 label 자체를 아무도 측정하지 않았다**가 답. 이 답이 통하지 않으면 F3는 없다
5. *"κ가 낮으면 무엇을 결론 내리는가"* → §3.3의 준비된 논리

| **2. Background & Motivation** | 한강 telemetry 계층 구조, 실제 데이터 볼륨·비용 수치, 운영자가 실제로 겪는 조회 비용. **`08` §2.1(b)의 C_query 실측** | 동기가 추상적이면 SC가 아니라 ML 워크숍 논문 |
| **3. Related Work** | 4개 계열을 명시 분리: ① FDI diagnosability(Krysander & Frisk 2008, Rosich 2012 — 정성 정리임을 먼저 인정) ② 적응 스트리밍(AWStream, Chameleon, Reducto, VideoStorm) ③ HPC 모니터링 비용(LDMS SC'14, DCDB SC'19, Netti FGCS'20의 미측정 인정 인용) ④ 모델측 축소(Prodigy SC'23, NodeSentry SC'25, Tuncer TPDS'19) + trace측(Gleaner, Mint ASPLOS'25, Hindsight NSDI'23) | 하나라도 빠지면 심사자가 그 논문으로 반박한다. **§1.12의 7개 반론이 모두 이 섹션에서 처리되어야 한다** |
| **4. Problem Formulation** | `09` §12.1의 π, C(π), Q(π), 제약 최소화. **Rosich Problem 3과의 4개 차이**(rate 변수, retention 변수, 연속 통계 품질, 해석적 모델 불요)를 표로 | formulation이 없으면 측정 논문이 되고 SC 본트랙에서 약해진다 |
| **5. Methodology** | 코퍼스 구성(`08` §4.2/4.3), 주입 프로토콜, GT 두 종류, baseline B0–B6, 지표 | GT-observed 규모를 숨기면 rebuttal에서 무너진다 |
| **6. Cost Characterization** | C_agent·C_network·C_storage·C_query·**C_perturb** 실측. rate × 규모 × 벤치마크 매트릭스 | C_perturb가 없으면 AWStream delta (ii)가 없다 = HPC 논문이 아니게 된다 |
| **7. Quality vs Resolution** | $Q_{detect}$/$Q_{RCA}$ 분리 곡선, 원인 클래스별 분해, **lag 재구성 오차로 설명** | 설명 없이 곡선만이면 H1a가 없다 |
| **8. Ordering-Preserving Policy** | B5의 설계와 B2 대비 결과. 같은 바이트 예산 비교 | **이 섹션이 논문의 기여다.** 없으면 측정 논문 |
| **9. Pareto Frontier & Policy Selection** | frontier, 계층적 정책(상시 저rate + 트리거 burst + 인시던트 pin), 운영 제약 하 선택 | 운영 적용이 없으면 SC의 실무 기대를 못 채운다 |
| **10. Cross-system** | §1.10 | 단일 시스템은 SC에서 반복적으로 지적된다 |
| **11. Limitations** | GT bias(silent degradation의 티켓 부재), 공개 데이터셋의 기집계 한계, 단일 벤더 fabric | 정직한 한계 절이 없으면 심사자가 대신 찾는다 |
| **12. Artifact** | 코퍼스 일부 릴리스(`08` §5.4), 정책 시뮬레이터, frontier 재현 코드 | AD/AE 배지는 SC에서 실질 가점 |

**워크숍에 머물게 하는 것:** 압축 파이프라인으로 프레이밍 / 품질 축이 탐지 하나 / C_perturb 미측정 / retention 축 없음 / 단일 탐지기 / ordering 섹션 없음.
**SC로 올리는 것:** retention을 1급 결정변수로 + 교란을 비용 항으로 + 진단을 품질 항으로 + ordering 메커니즘의 예측 검증 + 2시스템 이상.

## §5. F2 논문 구조

| 섹션 | 들어가야 하는 것 | 없으면 |
|---|---|---|
| Abstract | 세대 교체가 운영 ML을 무효화한다는 실무 문제 → 손실을 요인별로 분해 → transfer-penalty matrix 공개 | |
| 1. Intro | **측정/벤치마크 기여임을 명시.** adapter를 제안하지 않는다고 선언 | CENTILE와 방법 경쟁하면 진다 |

| 8. What Transfers | metric 수준 분석 — 어떤 신호가 세대를 넘는가 | 이것이 `08`/설계 권고로 환류되는 부분 |

## §6. F3 논문 구조

| 섹션 | 들어가야 하는 것 | 없으면 |
|---|---|---|
| Abstract | HPC 운영 label의 소스 간 불일치를 측정 → 구조화되어 있음 → 모델 평가를 편향시킴 → 프로토콜 제안 | |
| 1. Intro | *"모든 HPC 이상탐지 논문은 label을 가정한다. 그 label이 무엇인지 아무도 측정하지 않았다"* | 이 프레이밍이 없으면 weak supervision 응용 논문 |
| 2. Label Sources in Production | 5개 소스의 생성 경로와 의미를 기술 | 이 기술 자체가 커뮤니티 기여 |
| 3. Related Work | Uptake(ISSRE'24), label 효율 계열(partial/PU/AutoKAD/ALBADross), 평가 비판(Kim et al.), HPC RCA(Kaleidoscope, ARGUS, ClusterRCA, Tuncer) | |
| 4. Cause Taxonomy | 사전 정의 taxonomy와 설계 근거 | taxonomy가 사후 정의면 신뢰 불가 |
| 5. Measurement Protocol | gold set 구축, 복수 판정, κ, RMA 지연 채점, 계획-비계획 분리 | **재사용 가능한 프로토콜이 기여의 절반** |
| 6. Disagreement Structure | 소스 쌍별·클래스별 κ, 시간 정합, 감도(주입 기준) | |
| 7. Impact on Model Evaluation | B1–B6 label로 학습한 동일 모델의 보고 성능 차이 = H3a | **이 섹션이 없으면 관찰 논문** |
| 8. Fail-slow Cause Discrimination | 통일 label 위에서 내재적 vs 유발 판별, 특정 이웃 job 귀속 | C5 부분. Slingshot counter 의존 |
| 9. Limitations | 단일 센터, 운영자 수, silent degradation의 sampling bias | |
| 10. Artifact | gold set(가명화), 프로토콜 문서, taxonomy | |

**워크숍에 머물게 하는 것:** labeling function 만들고 F1 향상 보고 / 단일 소스 정답 가정 / κ만 보고 하류 영향 미측정 / 원인 클래스 3개 이하 / 탐지 전용.
